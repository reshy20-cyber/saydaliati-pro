# صيدليتي PRO — الإصدار 6 (حسابات + اشتراك داخل التطبيق + فروع وموظفون)

## ما الجديد
- تسجيل دخول بالبريد وكلمة المرور (بدل مفاتيح الترخيص).
- الاشتراك داخل التطبيق عبر RevenueCat (Google Play / App Store). الترقية لا تتم إلا داخل التطبيق.
- الأصناف في مجموعة فرعية لكل فرع: pharmacies/{id}/branches/{id}/stock (لا حد 1MB).
- فروع متعددة: لكل فرع مخزون وفواتير ومبيعات مستقلة.
- موظفون بأدوار: مالك (كل شيء) / مدير (كل شيء عدا الموظفين والفروع) / كاشير (بيع وعرض الفواتير فقط)، مع تقييد الموظف بفروع محددة.
- البيع يعمل دون إنترنت ويُزامن تلقائياً (increment دون تعارض).
- حذف الحساب من داخل التطبيق (شرط Apple).

## خطوات الإعداد (بالترتيب)
### 1) Firebase
1. Authentication > Sign-in method > فعّل Email/Password.
2. Firestore Database > Rules > الصق محتوى firestore.rules ثم Publish.
3. احذف البيانات القديمة (صيغتها مختلفة). لنقل أصنافك القديمة: صدّرها JSON من النسخة القديمة ثم استوردها من: الحساب > النسخ الاحتياطي > استيراد أصناف.

### 2) RevenueCat
1. أنشئ مشروعاً وأضف تطبيق Android وتطبيق iOS.
2. أنشئ Entitlement باسم: pro
3. أنشئ Offering (Current) فيه باقتين: Monthly و Annual مربوطتين بمنتجات المتجر.
4. انسخ المفتاحين العامين (Public SDK Key) للأندرويد وiOS.

### 3) المتاجر
- Google Play: Monetize > Subscriptions: أنشئ اشتراكاً شهرياً وسنوياً.
- App Store Connect: أنشئ Subscription Group بنفس المنتجين.

### 4) ملف src/config.js
ضع مفتاحي RevenueCat ورابطي سياسة الخصوصية وشروط الاستخدام (إلزامية لـ Apple).

### 5) البناء
npm install
npm run build
npx cap sync

## تنبيهات صريحة
- قواعد الأمان (firestore.rules) لم تُختبر على Firestore Emulator الحقيقي؛ اختُبرت عبر ترجمة لها في بيئة محاكاة. اختبرها في Rules Playground قبل النشر.
- حالة الاشتراك يكتبها تطبيق المالك، فيمكن تزويرها تقنياً. الحل لاحقاً: Webhook من RevenueCat + Cloud Function (يحتاج خطة Blaze).
- الشراء لم يُختبر فعلياً؛ يحتاج بناءً حقيقياً واختبار اشتراك Sandbox.
- حساب الموظف في Authentication لا يُحذف من التطبيق؛ يُعطَّل فقط.
- حد الفاتورة 15 صنفاً.
